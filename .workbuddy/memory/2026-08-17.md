## 插件市场(zat-dsh-engine)激活修复(重要坑)
- 现象:伴侣插件 `zat-dsh-engine` 已复制到 `~/.dsh/profiles/web/node_modules`,但 Web UI 看不到「插件市场」。
- 根因(三层):
  1. 引擎不内置 marketplace(lib 里搜 plugin-market 零命中),完全靠该外部插件。
  2. `deploy-extra.cjs` 的 `deployPlugins()` 只 `copyDir` 文件,**没有**把插件 `cordis.patch.yml` 的 `insert: plugin-market` 合并进 web profile 的 `cordis.patch.yml`(该文件原本只有 system-prompt)。
  3. `zat-dsh-engine` 离线包**缺 package.json**(无 main / 无 exports / 无 dsh.client),DSH 的 `cordis-plugin-loader` 与 `dsh-client-modules` 无法解析。
- 修复(已验证服务正常启动、HTTP 200):
  1. 在 `~/.dsh/profiles/web/cordis.patch.yml` 追加 `insert: plugin-market`(name: zat-dsh-engine),与 system-prompt 同级。
  2. 给 `zat-dsh-engine` 补 `package.json`(**源仓库 `dsh-extra/plugins/zat-dsh-engine/` 与部署目标两处都改**,保证幂等可复现),格式:
     ```json
     {
       "name": "zat-dsh-engine", "version": "0.0.0", "type": "module",
       "main": "lib/index.js",
       "exports": { ".": "./lib/index.js", "./client": "./lib/client.js" },
       "dsh": { "client": { "platform": "web" } }
     }
     ```
  3. 关键约束(从 `node_modules/@deepseek-ai/dsh-client-modules/lib/index.js` 的 `parseDshClient`/`resolveMeta` 反推):`dsh.client` 必须是**对象**且 `platform` 必须为 `"web"`;`exports` 必须含 `"./client"`(否则报 exports no ./client bundle);`exports` 还需 `"."` 主入口(否则 loader import 包名报 No exports main)。
- 失败即服务无法启动(plugin tree failed to load),每次改完需重启验证。当前 PID 224460,3090 端口正常。
- 进一步排障(刷新后仍看不到 tab):
  - `dsh-client-modules` 在 `resolveMeta` 里用 `createRequire(ctx.baseUrl)` 解析 `zat-dsh-engine/package.json`;由于我们补的 `exports` 没声明 `"./package.json"`,Node 报 `ERR_PACKAGE_PATH_NOT_EXPORTED`,被静默捕获后判定为"非 client 包",导致 boot graph 里没有该插件,`/plugins/zat-dsh-engine/client.js` 返回 404。
  - 修正:在 `package.json` 的 `exports` 中追加 `"./package.json": "./package.json"`(源仓库与部署目标同步更新)。
  - 验证:重启后 `index.html` 的 `window.__DSH_BOOT__` 已包含 `zat-dsh-engine`,`/plugins/zat-dsh-engine/client.js` 返回 200 且大小 68262;服务 PID 235608,3090 端口 HTTP 200 正常。
- 结论:原仓库 `deploy-extra` 对离线插件只做了"复制",漏了"注册/补 package.json(必须含 ./package.json export)",这是仓库本身缺陷。已手动补齐。

## 双击启动 bat "没效果" 根因与修复
- 现象:用户反馈双击 `启动DSH网页版.bat` 无反应。当时 3090 端口空闲(之前后台服务 PID 235608 已停)、`.env` 正常、node 在系统 PATH(`C:\Program Files\nodejs\`,双击 Explorer 能找到)。
- 根因:**两个 bat 文件带 UTF-8 BOM 头(`ef bb bf`)**。`cmd.exe` 双击解析时把 BOM 当命令一部分,首行 `@echo off` 解析异常,导致整脚本失效/无效果。与 node、端口、配置均无关。
- 修复:用 Write 工具重写 `启动DSH网页版.bat` 与 `start-dsh-web.bat`,去除 BOM(校验文件头已变 `40 65 63`=`@ec`),并在 `@echo off` 后加 `chcp 65001 >nul` 让中文提示在控制台正确显示。脚本逻辑不变。
- 验证限制:本环境 Git Bash 调 `cmd /c` 被安全策略拦截(`Invoking cmd.exe from Bash bypasses all command validation`),`cmd //c` 退化成交互模式无法执行 bat 主体,故无法用 headless 复现双击。改用直接 `node bin.js web --port 3090`(加载 .env)拉起验证:PID 37892,3090 LISTENING,HTTP 200,证明引擎+配置完好。用户可在真实桌面双击验证。
- **已提交并推送 bat 修复**:`git add start-dsh-web.bat "启动DSH网页版.bat"` → commit `ea3ec4d`(2 files / 4 insertions),随后 `git push origin main` 成功 → `440d017..ea3ec4d main->main`(GitHub 身份 QWQcool)。diff 已核对无密钥泄露(.env 未跟踪;"DEEPSEEK" 命中仅是注释里的品牌名误报)。
